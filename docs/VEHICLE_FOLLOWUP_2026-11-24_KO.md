# 11월 24일 — 전날 차량 창 반복 표시 조사

사용자는 전날 저절로 보였던 화면이 차량 제어 창이라고 확인했습니다. REA로 최신 앱 상태·activation·display 파일을 읽고 기존 로컬 보관본과 대조했습니다. 앱을 실행하거나 창을 열지 않았으며 재설치도 하지 않았습니다.

전날 기록은 빌드 64입니다. 남아 있는 기록에는 새로운 `vehicle.panel.widget`, `vehicle.panel.in-app`, `vehicle.quick.intent` 진입 표식이 없습니다. 21일의 위젯 진입 표식이 남은 같은 프로세스의 재활성화는 기록돼 있습니다. 회전·누락된 과거 기록도 있으므로 새 요청이 절대로 없었다고 보장하지 않습니다.

64 소스는 차량 창의 `presented=true`를 백그라운드 전환에서 해제하지 않았습니다. 이 경로와 사용자의 화면 설명은 **남아 있던 차량 창의 재표시**에 부합합니다. 당시 `renderedSurface`는 실제 sheet/view 상태가 아닌 마지막 진입에서 추정한 값입니다. 재활성화 수를 실제 화면 표시 횟수로 해석하지 않습니다. OS가 앱을 전면 복귀시킨 정확한 계기는 여전히 미확정입니다.

이 경로의 정리는 오늘 설치한 **0.5.32 / 빌드 66**에 포함됐습니다. 최신 66 상태는 백그라운드 연결·인증 완료, 차량 창 표시 요청과 view 표시 플래그 false입니다. 읽은 66 display 구간에도 차량 진입 요청이 없고, 전용 차량 파일은 아직 없었습니다. 향후 재발 여부나 모든 OS 화면 전환을 관찰할 수 있다는 결론은 아닙니다. [설치와 기록 범위](DEPLOYMENT_0.5.32_KO.md).
