# 11월 25일 — 메인 화면 재등장

사용자는 차량 제어 창이 아닌 연결 상태 메인 화면이 저절로 보였다고 보고했습니다. REA로 설치본 **0.5.32 / 빌드 66**의 상태·화면 이벤트·활성화 요약·연결 이벤트를 읽었습니다. 이번 조사에서 앱 실행·재설치·창 열기는 하지 않았습니다.

## 관측 사실

- 보고 수집 시각은 13:16 KST이며 가장 가까운 메인 scene 활성화는 **13:13:48 KST**입니다. 발생 시각을 사용자가 직접 지정한 것은 아니므로 두 시각을 동일 사건이라고 확정하지 않습니다.
- 어제 설치 후 계속 실행 중인 같은 프로세스입니다. 새 프로세스 실행이나 차량 창 표시 요청이 아닙니다. 차량 창의 표시 요청·view 표시 플래그는 모두 false입니다.
- 12:50:39에 foreground 진입을 기록한 뒤 inactive/active 전환이 반복됐고, 13:13:48에도 inactive → active → scene.active가 기록됐습니다. 13:13:52에는 background로 돌아갔습니다.
- 해당 빌드의 보관된 320개 화면 이벤트에 알림 열기, 사용자 활동, 차량 위젯 진입 표식은 없습니다. 27개 scene.active를 모두 사용자가 보고한 자동 열림 횟수로 해석하지 않습니다.
- 관련 활성화 시점에 BLE 연결·인증은 이미 정상이었고 위치 세션은 eligible입니다. 재연결이나 위치 세션 재생성이 화면을 열었다는 인과관계는 입증되지 않았습니다.

## 해석과 남은 문제

이 반복 전환은 watchOS의 frontmost 앱 재표시 동작과 일치합니다. Apple은 비활성 상태로 남은 frontmost 앱이 손목을 들면 다시 활성화되고, Crown으로 시계 화면에 돌아가면 background로 전환된다고 설명합니다. 위치 활동 앱도 비슷하게 동작할 수 있습니다. [Apple 문서](https://developer.apple.com/documentation/watchkit/taking-advantage-of-frontmost-app-state).

그러나 기록에 없는 첫 foreground 진입의 정확한 계기까지 설명하는 근거는 아닙니다. 위치 세션이 원인이라는 단정, 차량 창 정리 수정으로 메인 화면 문제도 해결됐다는 결론, 사용자가 알림이나 위젯을 눌렀다는 추정은 하지 않습니다. **메인 화면 자동 표시 문제는 미해결이며 실사용 재발 조사 대상으로 다시 활성화합니다.** 이번 변경은 조사 문서뿐이며 앱 실행 동작과 설치 버전은 유지합니다.
