# 워치 0.5.31 — 백그라운드에 남는 차량 창 정리

**후속 결과 — 2026-11-24:** 0.5.32 / 빌드 66 설치와 백그라운드 실행 완료. 아래의 11월 23일 실패·대기 상태는 당시 기록입니다. [최신 설치 기록](DEPLOYMENT_0.5.32_KO.md).

워치·위젯 소스 **0.5.31 / 빌드 65**. 폰은 **0.6.23 / 코드 45**입니다. 빌드는 완료했으며 기기 설치 결과는 아래 후속 기록을 따릅니다.

## 사용자 답변과 코드에서 좁힌 문제

사용자는 11월 23일 저절로 보였던 화면이 **시동·문 잠금 등이 있는 차량 제어 창**이라고 확인했습니다. 앞선 자동 기록에는 11월 21일 18:13의 `vehicle.panel.widget` 이후 차량 창 닫힘 표식이 없고, 11월 23일에는 같은 프로세스가 연결·인증된 상태에서 재활성화됐습니다. [확보한 기록](DISPLAY_OBSERVATION_2026-11-23_KO.md).

차량 창은 `VehicleQuickRouter.presented`에 연결된 SwiftUI sheet입니다. 기존 코드는 위젯·앱 내부 버튼으로 이를 true로 만들고, 사용자가 닫기 동작을 하기 전에는 백그라운드로 가도 값을 해제하지 않았습니다. 그래서 오래된 창이 다음 전면 복귀 때 유지될 수 있었습니다. 이는 **왜 차량 창이 계속 남았는지**에 해당하는 코드 경로이며, watchOS가 어떤 이유로 앱을 전면 복귀시켰는지까지 확정하는 것은 아닙니다.

## 변경한 동작

- 한 번 실제 활성화됐던 차량 창은 앱이 SwiftUI `background`로 갈 때 닫습니다. 단순 `inactive` 전환에는 닫지 않습니다.
- 새 위젯 진입이 아직 최초 활성화되기 전이라면 초기 배경 전환만으로 새 요청을 지우지 않습니다.
- 자동 창 닫기와 사용자의 닫기를 구분합니다. 자동 닫기의 sheet/view 종료 콜백은 이미 사용자가 시작한 명령 준비·응답 처리를 추가로 취소하지 않습니다. 사용자 닫기와 화면 이동의 기존 취소 동작은 유지합니다. 자동 닫기는 명령을 새로 만들거나 재전송하지 않습니다.
- 진입 문자열만으로 화면 종류를 추정하던 기록을 보완했습니다. `presented`의 실제 변경마다 `vehicle.panel.presented`, `vehicle.panel.hidden`을 기록하고, 자동 닫기 및 완료 표식을 남깁니다. 상태 파일에도 실제 `vehiclePanelPresented`를 기록합니다. 이 값은 앱의 표시 요청 상태이며 실제 물리 화면 관찰과 구분합니다.

BLE 인증·재연결·위치 세션·설치 ID·키·등록·차량 버튼 지정은 변경하지 않았습니다. 시스템 로그·관리자 인증·실제 차량 제어·별도 거리/잠금 시험은 진행하지 않습니다. 초기 설치·실행 기록만 앱 자체 파일과 REA로 남깁니다.

## 설치 상태

빌드 완료. Mac–워치 개발 터널이 다시 시간 초과돼 연결·잠금 해제 준비를 기다립니다. 설치 전에는 소유자 설치본 0.5.30 / 64와 개인 자동 갱신 소스를 유지합니다. 설치 성공 뒤에만 갱신 소스·설치 메타데이터를 65에 맞춥니다.
