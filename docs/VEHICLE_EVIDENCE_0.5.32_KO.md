# 워치 0.5.32 — 차량 창 자동 원인 기록

워치·위젯 소스 **0.5.32 / 빌드 66**. 폰은 0.6.23 / 코드 45로 유지합니다.

## 확정한 범위와 남은 원인

사용자는 차량 제어 창을 누른 적이 없다고 추가로 설명했습니다. 기존 `vehicle.panel.widget`는 `OpenVehicleControls.perform` 진입을 뜻하며 실제 터치 증거가 아닙니다. 0.5.31의 남은 창 정리는 재표시 가능한 경로를 수정한 것이고, 누르지 않은 창의 최초 열림이나 watchOS의 전면 복귀 원인을 확정한 것이 아닙니다.

## 자동으로 남기는 내용

- 차량 창 열기 요청마다 새 요청 ID, 시각, 요청 전 창 상태, 프로세스·빌드·앱 상태·연결 상태를 기록합니다. 이미 열린 창에 다시 요청돼도 기록합니다.
- 진입 지점을 `OpenVehicleControls.perform`, `RunVehicleQuickControl.perform`, 앱 메인 버튼, 차량 창 버튼, 모든 제어 화면 버튼으로 나눕니다. 명령 종류는 내부 enum 값만 기록하며 차량 정보나 알림 본문은 담지 않습니다.
- sheet의 표시 요청(`presented`)과 실제 SwiftUI view의 appear/disappear 콜백을 따로 기록합니다. 모든 제어·빠른 설정 화면 이동도 남깁니다. view 콜백도 물리 화면이나 실제 터치의 직접 관찰은 아닙니다.
- 차량 화면이 나타나거나 차량 창을 유지한 채 앱이 재활성화되면 직전 이벤트 48개와 차량 이벤트 16개를 자동 스냅샷으로 보관합니다. 사용자가 ‘화면 문제 기록’을 누를 필요가 없습니다.

앱 Documents 아래 `watchbridge-vehicle-panels.json`은 차량 이벤트 256개, `watchbridge-vehicle-panel-snapshots.json`은 스냅샷 16개를 보관합니다. 기존 display 이벤트·activation 기록도 유지합니다. 이 용량을 넘으면 가장 오래된 기록부터 교체합니다. 재발 직후 REA로 앱 자체 파일을 읽어 새 요청 여부와 예전 창 복귀를 구분할 수 있습니다. 기록이 저장되지 못하거나 앱이 실행되지 않은 구간, 보관 한도를 넘은 과거는 알 수 없습니다.

## 적용 상태

빌드 완료. 0.5.31 설치 시도는 Mac–워치 개발 터널 시간 초과로 실패했습니다. 소유자 설치본과 주간 자동 갱신 소스는 설치 성공 전까지 0.5.30 / 64로 유지합니다. 66의 설치 결과는 후속 기록을 따릅니다. 기존 등록·차량 설정·BLE·위치 연결 유지·서명 예약은 변경하지 않습니다.
